GitHub Copilot をエージェント モードにすると、コードベースを調査し、変更を提案し、ファイルを編集して、コマンドを実行します。VS Code の Copilot Chat では、作業がローカル マシンでリアルタイムに進むため、ツール呼び出しやファイル編集の状況を確認できます。各差分をインラインでレビューし、個々の変更を承認または取り消し、エディターを離れずに追加のプロンプトで会話を導き、作業を調整または拡張できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視する。
- 提案されたファイル編集をレビューして適用する。
- 実行中のセッションに指示を出し、ハイ コントラストに加えてライト モードの切り替えを追加する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中にデザイン チームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加します。新しい会話を始めるのではなく、既存のセッションに指示して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューでは、エージェントが実行する手順を確認できます。エージェントが調べるファイル、実行するコマンド、提案する編集が表示されます。ファイルの編集は差分と **Keep** / **Undo** 操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナル コマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がインラインで表示されます。
    - **Keep** を選択すると変更を適用します。
    - **Undo** を選択すると変更を元に戻し、エージェントに再度試すよう促します。
4. チャット上部の **Files changed** インジケーターを開くと、このセッション中にエージェントが変更したファイルをすべて確認できます。

> [!NOTE]
> ターミナル コマンドの実行などでツールの許可が必要な場合、エージェントは一時停止して **Allow** の確認を求めます。内容を確認し、許可できるコマンドだけを承認してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。変更内容をまとめた最終メッセージが表示されます。

## エージェントにライト モードを追加するよう指示する

ハイ コントラスト モードを追加したら、同じ会話にライト モードの切り替えも追加します。同じチャット セッションを続けるため、エージェントは前の作業で変更したコンポーネント、スタイルの方針、ローカル ストレージの使い方を引き続き把握しています。

1. Copilot Chat の入力欄で、次のフォローアップ プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前回の変更を調べ、ライト モードの追加を提案します。
3. ハイ コントラストのときと同じように、新しい編集を確認します。それぞれの差分で **Keep** または **Undo** を選択します。
4. エージェントが望まない方向に進んだ場合（たとえば、好ましくない方法で切り替え UI をリファクタリングする場合）、チャット入力欄の横にある **Stop** ボタンで停止し、明確な追加メッセージを送信します。

> [!TIP]
> 実行中のセッションに指示する方が、最初からやり直すよりも短時間で済みます。フォローアップ プロンプトで、「CSS を簡素化し、セレクターを重複させずに CSS 変数を使う」などの調整や、「切り替えを 3 つにせず、既存の設定パネルにライト モードを追加する」などの軌道修正、「両方の切り替えにキーボード ショートカットも追加する」などの範囲拡張を依頼できます。

## 変更されたファイルをレビューする

コミットする前に、エージェントが変更した内容をひととおり確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、ローカル ストレージによる設定の保持など、カスタム エージェントが指示したアクセシビリティのパターンが反映されていることを確認します。
4. 問題がなければ、Source Control パネルで変更をステージしてコミットします。[次のレッスン][next-lesson]で公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使い、実行中のセッションを監視して指示しました。ファイル編集ごとにレビューし、変更を適用または取り消し、コンテキストを保持したままフォローアップ プロンプトで作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視する
- 個々のファイル編集を適用または取り消す
- 作業中のセッションに追加の指示を出す
